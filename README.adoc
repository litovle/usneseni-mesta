= Parsování usnesení města Litovel

image:https://github.com/litovle/usneseni-mesta/actions/workflows/sync-litovel-notices.yml/badge.svg[Synchronizace úřední desky,link=https://github.com/litovle/usneseni-mesta/actions/workflows/sync-litovel-notices.yml]

:toc:
:toclevels: 2

Pipeline pro strukturované zpracování a tematickou klasifikaci usnesení Rady
a Zastupitelstva města Litovel.

Cílem je:

- převod PDF do strukturované podoby,
- extrakce struktury usnesení,
- tematická klasifikace finálním lokálním modelem,
- resolvování vzájemných referencí,
- vytvoření fulltextového indexu,
- statický export do Jekyll struktury,
- parsování a propojení rozpočtových opatření,
- maximální reprodukovatelnost a auditovatelnost.

Runner má tři pojmenované etapy. Jednotlivé operace zůstávají samostatnými
skripty pro testování a cílené opakování. Extrakce a analýza ukládají usnesení
samostatně; resolvování referencí je sloučí a export zapisuje JSON po letech.

== Architektura

Produkční inferenční modul `resolution_classification/` je součástí tohoto
repozitáře a musí být commitnutý společně s jeho metadaty a integračními testy.
Samostatný repozitář `litovel-resolution-classifier` spravuje trénink, kurátorované
datasety a modelové releasy. Pipeline z něj načítá pouze versionovaný artefakt
přes URL a SHA-256; nepotřebuje jeho checkout ani Python balíček.

Podrobný tok dat, role modulů, schéma rozhodnutí, formát modelového balíčku
a provoz v GitHub Actions popisuje
link:docs/classification-architecture.md[Architektura tematické klasifikace].

Pipeline má tři etapy; publikování přes pull requesty zůstává v GitHub Actions:

[cols="1,3"]
|===
|Extract
|Parsování PDF usnesení a rozpočtových opatření, doplnění podporovaných archivních záznamů

|Enrich
|Analýza a klasifikace usnesení, resolvování referencí a volebních období, propojení rozpočtových opatření

|Export
|Indexy a roční JSON z finálních obohacených dat; jeden statický export stránek a sitemap
|===

GitHub Actions parsuje pouze PDF uvedená v manifestu, zachová uložený korpus
a spustí Enrich → Export. Klasifikace, reference a rozpočtové vazby se přepočítají
nad celým korpusem. Export samotný neopakuje parsování ani inference.

== Pipeline skript

Všechny fáze lze spustit najednou pomocí `pipeline.py`.

=== Použití

[source,bash]
----
# Celý pipeline od začátku s daty v tomto repozitáři
python pipeline.py --pdf resources

# Obohatit již extrahovaný korpus a přegenerovat export (také Actions)
python pipeline.py --from-stage enrich --to-stage export

# Spustit pouze extrakci nebo pouze obohacení
python pipeline.py --pdf resources --to-stage extract
python pipeline.py --from-stage enrich --to-stage enrich

# Vlastní pracovní adresář a výstup
python pipeline.py --pdf pdf_dir/ --workdir moje_data/ --export vystup/

# Export existujících finálních dat bez opakování klasifikace
python pipeline.py --from-stage export

# Vlastní adresář s PDF rozpočtových opatření
python pipeline.py --pdf resources --ro-pdf resources/rozpoctova-opatreni

# Samostatný výstup usnesení bez RO; existující exportované soubory se nemažou
python pipeline.py --pdf resources --without-budget --export export-usneseni

# Zobrazit příkazy bez spuštění
python pipeline.py --pdf pdf_dir/ --dry-run
----

=== Adresářová struktura

[source]
----
resolution_classification/       ← produkční inference a adaptér pipeline
tests/test_classifier_bundle.py ← testy stažení, integrity a cache modelu
tests/test_pipeline_classification.py ← testy zapojení do pipeline
.cache/resolution-classifier/    ← stažené váhy (ignorované Gitem, cache v Actions)
----

Historické trénovací skripty, vývojové datasety a reporty byly přesunuty do
`development-archive/` repozitáře klasifikátoru. Staré váhy a trénovací checkpointy
byly odstraněny. `work/classifier/` jsou nové generované predikce a reporty
produkčního běhu; neslouží jako cache modelových vah.

=== Tematický klasifikátor

Enrich automaticky používá finální tematický model `v1.0.0` s taxonomií `v7`.
Váhy se stáhnou z versionované GitHub Release URL. Pipeline nepotřebuje checkout
ani instalaci repozitáře klasifikátoru:

[source,bash]
----
python -m pip install -r requirements.txt
python pipeline.py --from-stage enrich --to-stage export
----

Výchozí URL:
`https://github.com/litovle/litovel-resolution-classifier/releases/download/v1.0.0/litovel-resolution-classifier-v1.0.0.tar.gz`.
Při prvním použití se ověří SHA-256 a model se uloží do
`.cache/resolution-classifier`. Další běhy použijí ověřenou cache. Inference
probíhá lokálně. `--classifier-url URL` a `--classifier-sha256 SHA` umožňují
zvolit jiný versionovaný balíček; `--classifier-cache DIR` mění umístění cache.
Pro lokální archiv lze použít URL `file:///absolutni/cesta/model.tar.gz`.

Modelový archiv musí obsahovat `model/config.json`, `model/tokenizer.json`,
`model/tokenizer_config.json` a `model/model.safetensors`. Kategorie určuje
mapování `id2label` v konfiguraci modelu. Metadata z trénování ani ruční opravy
pipeline nepoužívá.

Každé usnesení v analyzovaných, resolvovaných a exportovaných ročních JSON datech
obsahuje objekt `classification`: kategorii z modelu, zdrojové URL a SHA-256
archivu, stav a skóre modelu. Chybějící nebo duplicitní predikce a nesoulad
vstupního textu zastaví pipeline. Predikce a fronta pro kontrolu se ukládají do
`work/classifier`. Nízké skóre kategorii nemění.
Při novém běhu Enrich se klasifikace přepočítá; samostatný Export používá
klasifikace uložené předchozím během Enrich.

Oba GitHub Actions workflows instalují CPU variantu PyTorch a uchovávají cache
modelu přes `actions/cache`. URL a checksum lze změnit pomocí repository
variables `RESOLUTION_CLASSIFIER_URL` a `RESOLUTION_CLASSIFIER_SHA256` (nastavte
obě společně). Cache modelu není součástí generovaných pull requestů.
Číselné volby `--from-phase` a `--to-phase` byly nahrazeny pojmenovanými etapami.
Historické názvy skriptů a pracovních adresářů jsou interní konvence.

[source]
----
pdf_dir/          ← vstupní PDF soubory (rekurzivně prohledáváno)
work/phase1/      ← Extract: syrové usnesení
work/phase3/      ← Enrich: analýza a classification
work/phase4/      ← Enrich: resolvované reference a volební období
work/classifier/  ← predikce finálního tematického modelu a fronta pro kontrolu
work/rozpoctova-opatreni/        ← Extract: rozpočtová opatření
work/rozpoctova-opatreni-linked/ ← Enrich: finální usnesení a rozpočtové vazby
work/archive_rm/  ← pracovní data historického archivu rady města
work/archive_zm/  ← pracovní data historického archivu zastupitelstva
export/assets/usneseni/    ← Export: index a roční data z finálního usneseni.json
export/assets/usneseni/ro/ ← Export: index RO
export/           ← Export: jednou generované stránky a sitemap
----

=== Parametry

[cols="1,3"]
|===
|`--pdf DIR`
|Adresář se vstupními PDF usnesení. Prohledává se rekurzivně. Povinný jen při
spuštění Extract. Pokud adresář obsahuje i `--ro-pdf`, rozpočtová opatření se
při parsování usnesení přeskočí.

|`--ro-pdf DIR`
|Adresář se vstupními PDF rozpočtových opatření (výchozí:
`resources/rozpoctova-opatreni`)

|`--workdir DIR`
|Pracovní adresář pro meziproduktová data (výchozí: `work/`)

|`--export DIR`
|Cílový adresář statického exportu (výchozí: `export/`)

|`--from-stage STAGE`
|Začít od `extract`, `enrich` nebo `export` (výchozí: `extract`).

|`--to-stage STAGE`
|Skončit po zvolené etapě (výchozí: `export`). Rozsah musí odpovídat pořadí etap.

|`--without-budget`
|Přeskočit parsování, propojení a export RO. Použije resolvované usnesení z
`work/phase4/usneseni.json` a vypne autodetekci RO. Existující výstupní soubory nemaže.

|`--dry-run`
|Pouze zobrazí příkazy, nespustí je

|`--archive-root DIR`
|Archivní pracovní adresář s `archive_documents.json` a `extraction.json`.
Moderně strukturovaná archivní usnesení se při fázi 1 doplní do `work/phase1`.
Volbu lze opakovat. Pokud není uvedena, použijí se existující
`work/archive_rm` a `work/archive_zm`.

|`--no-archive-current`
|Vypne doplnění archivních dokumentů ve formátu současných usnesení do hlavní
pipeline.

|`--classifier-url URL`
|URL modelového archivu. Výchozí je veřejný, versionovaný release v1.0.0.

|`--classifier-sha256 SHA`
|Očekávaný SHA-256 archivu; měňte společně s URL.

|`--classifier-cache DIR`
|Cache ověřených modelů (výchozí: `.cache/resolution-classifier`).

|`--terms FILE`
|Volitelný JSON seznam volebních období pro fázi resolvování referencí.
Používá se k doplnění `term_id` a `term_label` do usnesení a exportovaných
stránek.
|===

== Automatická synchronizace úřední desky

GitHub Actions workflow `Synchronizace úřední desky` denně kontroluje aktuální
oznámení na úřední desce Litovle a hledá nové dokumenty:

- výpisy usnesení rady nebo zastupitelstva,
- rozpočtová opatření.

Nové PDF uloží do `resources/`, naparsuje jen nově stažené soubory, přegeneruje
navazující data a připraví jeden pull request v tomto repozitáři a jeden pull
request v `litovle/litovle.cz`. Workflow lze spustit i ručně přes
`workflow_dispatch`; volba `dry_run` pouze vypíše, co by se stáhlo. Pokud
automatický běh selže, workflow založí nebo okomentuje issue přiřazenou správci.

Pro pull request do `litovle.cz` musí být v tomto repozitáři nastavený secret
`LITOVLE_CZ_PAT` s oprávněním zapisovat obsah a vytvářet pull requesty v
`litovle/litovle.cz`.

=== Ruční zpracování PDF

Pokud automatická synchronizace selže například kvůli ochraně webu, lze z
mobilního GitHub rozhraní použít workflow `Zpracování ručně přidaného PDF`.

Nejjednodušší postup:

1. stáhnout PDF ručně v prohlížeči,
2. přiložit PDF do GitHub issue nebo komentáře,
3. zkopírovat URL přílohy,
4. spustit workflow `Zpracování ručně přidaného PDF`,
5. vyplnit `document_type`, `pdf_url`, případně `target_filename` a
   `resolution_target`.

Workflow PDF uloží do správného adresáře v `resources/`, naparsuje jej,
přegeneruje návazná data a připraví pull requesty v obou repozitářích.
Alternativně lze vyplnit `pdf_path`, pokud už je PDF v repozitáři.

== Extract: parsování PDF usnesení

Parsování PDF s usneseními Rady nebo Zastupitelstva města Litovel.

Při spuštění přes `pipeline.py` se po běžném parsování PDF může doplnit také
moderní část archivu. Dokumenty z archivu, které v extrahovaném textu obsahují
bloky `Číslo: RM/.../.../...` nebo `Číslo: ZM/.../.../...`, se zapíší jako
běžné záznamy extrakce a projdou současnou pipeline. Starší archivní dokumenty
bez tohoto formátu zůstávají v samostatném archivním zpracování.

Hranice mezi současnou a archivní větví je tedy formát dat, ne původní stránka:
záznamy s kanonickým ID `RM/.../.../...` nebo `ZM/.../.../...` patří do
současné pipeline, archivní větev zůstává fallbackem pro starší nebo nejisté
dokumenty.

Samostatné zpracování historického archivu je popsané v
`docs/archive-zm.md`. Veřejný archiv se exportuje pod `/usneseni/archiv/` jako
přehled podle roku, orgánu a schůze. Dokumenty, které splitter bezpečně rozdělí,
mají přehledovou stránku schůze se seznamem jednotlivých archivních usnesení.
Nerozdělené dokumenty zůstávají jako fallback detail a jejich počet se zobrazuje
jen v souhrnu archivní stránky.

=== Vstup

- jeden PDF soubor
- NEBO složka s PDF soubory (při spuštění přes `pipeline.py` se prohledávají i podsložky rekurzivně)

=== Výstup

- jeden JSON soubor = jedno usnesení

=== Použití

[source,bash]
----
python phase1_parse_pdf.py input.pdf output_dir/
python phase1_parse_pdf.py pdf_dir/ output_dir/
----

== Enrich: analýza a tematická klasifikace

Zpracuje syrové JSON z Extract.

=== Vstupní struktura

[source,json]
----
{
  "id": "RM/1/1/2022",
  "datum": "2022-10-27",
  "organ": "Rada města Litovel",
  "text_raw": "text_usneseni"
}
----

=== Výstupní struktura

[source,json]
----
{
  "id": "RM/1/1/2022",
  "datum": "2022-10-27",
  "organ": "Rada města Litovel",
  "actions": [
    "schvaluje",
    "souhlasí"
  ],
  "subject": null,
  "items": [
    {
      "label": "a",
      "text": "text_1"
    },
    {
      "label": "b",
      "text": "text_2"
    }
  ],
  "tail": null,
  "references_out": [],
  "amounts": [
    "10.000 Kč"
  ],
  "classification": {
    "category": "property",
    "source": "model",
    "status": "classified",
    "model_url": "https://github.com/litovle/litovel-resolution-classifier/releases/download/v1.0.0/litovel-resolution-classifier-v1.0.0.tar.gz",
    "model_sha256": "6ad39105467ebd487349bb9b3ef6f2ea5ffcdf360ae1ac1190d410d7ebc0d69a",
    "prediction": {
      "category": "property",
      "confidence": 0.9,
      "second_category": "transport",
      "second_confidence": 0.04,
      "margin": 0.86,
      "entropy": 0.5
    }
  }
}
----

=== Co operace dělá

- extrahuje akce (např. „schvaluje", „bere na vědomí"),
- rozděluje vícepoložková usnesení na jednotlivé body,
- odděluje `subject` (text před body) a `tail` (text za body),
- extrahuje peněžní částky,
- hrubě extrahuje reference (bez resolvování).
- při běhu přes pipeline přiřadí tematickou kategorii, uchová původní predikci
  a ověřené URL a SHA-256 modelového archivu.

Ukázkové kategorie a skóre v JSON výše jsou ilustrativní. `classification` se
přidává při spuštění přes `pipeline.py` nebo při zadání `--classifier-url`.
Samostatný příkaz bez URL provádí pouze strukturální analýzu. Skóre modelu
není kalibrovaná pravděpodobnost správnosti; nízké skóre samo o sobě kategorii
neodebere. Známé nejednoznačné případy mají `category: null`.

=== Použití

[source,bash]
----
# Produkční analýza a klasifikace extrahovaných usnesení
python pipeline.py --from-stage enrich --to-stage enrich

# Samostatná strukturální analýza bez klasifikace
python phase2_resolution_analysis.py --input phase1_dir/ --output phase3_dir/
----

== Enrich: resolvování referencí

Usnesení mohou odkazovat jedno na druhé.
V této fázi se resolvují reference:

- implicitní +
  např. `1853/60` → `RM/1853/60/2025`
- explicitní +
  např. `RM/1853/60/2025`

Resolvované reference:

- jsou doplněny do nového klíče `references_in`,
- vztah je oboustranný.

Implicitní reference se resolvují v rámci stejného orgánu (`RM` odkazuje na
`RM`, `ZM` na `ZM`) a pouze na kandidáty, které nejsou datem později než
zdrojové usnesení. To chrání odkazy po volbách, kdy se číslování schůzí a
usnesení začne znovu od 1.

Fáze zároveň doplňuje metadata volebního období (`term_id`, `term_label`).
Výchozí hranice lze přepsat volbou `--terms`:

[source,json]
----
[
  {"id": "2022-2026", "label": "Volební období 2022-2026", "start": "2022-09-24", "end": "2026-10-10"},
  {"id": "2026-2030", "label": "Volební období 2026-2030", "start": "2026-10-10", "end": null}
]
----

Na závěr jsou vypsány statistiky do konzole.

=== Vstup

- adresář s JSON soubory z analýzy v Enrich

=== Výstup

- `usneseni.json` – seznam všech usnesení s rozřešenými referencemi
- `refs_index.json` – index rozřešených referencí
- `stats_refs.json` – statistiky resolvování

=== Použití

[source,bash]
----
python phase3_resolve_references.py --input phase3_dir/ --output phase4_dir/
python phase3_resolve_references.py --input phase3_dir/ --output phase4_dir/ --terms terms.json
----

== Export: index a roční JSON usnesení

Vytvoří index pro fulltextové vyhledávání.

Veřejné vyhledávání na webu načítá podle výchozího nastavení posledních 5 let,
aby první dotaz nestahoval celý historický archiv. Explicitní výběr roků v URL
nebo ve filtru toto omezení přepíše.

=== Vstup

- `work/rozpoctova-opatreni-linked/usneseni.json` z finálního Enrich;
  při `--without-budget` se používá `work/phase4/usneseni.json`.

=== Výstupní struktura

- `index/` – jeden JSON soubor = jeden rok (fulltextový index)
- `data/` – jeden JSON soubor = jeden rok (usnesení)
- `meta.json` – statistická metadata (např. počty rozhodnutí za roky)

=== Použití

[source,bash]
----
python phase4_index_build.py --input work/rozpoctova-opatreni-linked/usneseni.json --output export/assets/usneseni/
----

== Export: režim pouze usnesení

Generuje statické stránky ve struktuře vhodné pro Jekyll.

Vytváří:

- jednotlivé stránky usnesení,
- roční indexy,
- `sitemap-usneseni.xml` pro generované stránky usnesení.

Negeneruje hlavní stránku `/usneseni/` (ta existuje ručně). Nepřepisuje hlavní `sitemap.xml`; sitemap index má vlastnit web nebo projekt, který statický export publikuje.

=== Vstup

- `usneseni.json` z resolvování referencí (režim bez RO)

=== Výstupní struktura

[source]
----
export/
  usneseni/
    {rok}/
      {slug}/
        index.html   ← stránka jednotlivého usnesení
      index.html     ← roční přehled
  sitemap-usneseni.xml
----

=== Použití

[source,bash]
----
python phase5_static_export.py --input phase4_dir/usneseni.json --output export_dir/ --without-budget
----

Název sitemap souboru lze změnit volbou `--sitemap-filename`, výchozí hodnota je `sitemap-usneseni.xml`.

== Enrich: propojení rozpočtových opatření

Po parsování lze vytvořit odvozenou datovou vrstvu, která propojí:

- rozpočtové opatření se schvalujícími usneseními uvedenými v záhlaví PDF,
- usnesení s konkrétními rozpočtovými změnami `RZ`, pokud jsou v textu usnesení
  uvedeny přímo nebo rozsahem.

[source,bash]
----
python crosslink_rozpoctova_opatreni.py \
  --resolutions work/phase4/usneseni.json \
  --opatreni work/rozpoctova-opatreni \
  --output work/rozpoctova-opatreni-linked
----

Výstup:

- `usneseni.json` – kopie usnesení doplněná o vazby na rozpočtová opatření,
- `rozpoctova-opatreni/` – kopie rozpočtových opatření doplněná o vazby na usnesení,
- `budget_change_index.json` – index rozpočtových změn podle `RZ`,
- `stats.json` – statistiky a případné opravy zjevných překlepů v odkazech.

Statický export lze následně vygenerovat z již propojených dat bez opakování
obohacení:

[source,bash]
----
python pipeline.py --from-stage export
----

Stránky usnesení pak obsahují také sekci `Rozpočtová opatření`, pokud má dané
usnesení vazbu na konkrétní `RO` nebo `RZ`. Export zároveň generuje samostatné
statické stránky rozpočtových opatření:

[source]
----
export/
  rozpoctova-opatreni/
    index.html
    RO-6-2026/
      index.html
----

Rozpočtové změny (`RZ`) jsou odkazy na kotvy uvnitř stránky příslušného
rozpočtového opatření, např.:

[source]
----
/rozpoctova-opatreni/RO-6-2026/#rz-53-2026-rm
----

== Export: index rozpočtových opatření

Vytvoří fulltextový index rozpočtových opatření pro frontendové vyhledávání.
Index se generuje z propojených RO JSON dat a ukládá se přímo do exportní
struktury webu.

=== Vstup

- adresář `work/rozpoctova-opatreni-linked/rozpoctova-opatreni`

=== Výstupní struktura

- `export/assets/usneseni/ro/index/` – fulltextový index po rocích
- `export/assets/usneseni/ro/data/` – RO data po rocích
- `export/assets/usneseni/ro/meta.json` – metadata indexu

=== Použití

[source,bash]
----
python phase4_ro_index_build.py \
  --input work/rozpoctova-opatreni-linked/rozpoctova-opatreni \
  --output export/assets/usneseni/ro
----

== Export: finální statické stránky

Přegeneruje statický web nad propojenými daty tak, aby stránky usnesení
obsahovaly vazby na `RO` a současně vznikly samostatné stránky rozpočtových
opatření.

Na stránkách rozpočtových opatření se u jednotlivých `RZ` zobrazuje plný text
poznámky z PDF, pokud je k dané změně k dispozici. Účetní řádky zůstávají
zobrazené pod tímto vysvětlením.

=== Vstup

- `work/rozpoctova-opatreni-linked/usneseni.json`
- `work/rozpoctova-opatreni-linked/rozpoctova-opatreni/`

=== Použití

[source,bash]
----
python phase5_static_export.py \
  --input work/rozpoctova-opatreni-linked/usneseni.json \
  --opatreni work/rozpoctova-opatreni-linked/rozpoctova-opatreni \
  --output export
----

== Principy návrhu

- Extrakce a analýza uchovávají usnesení samostatně; další operace vytvářejí agregovaná data.
- Strukturální parsování je oddělené od modelové tematické klasifikace.
- Modelový archiv je identifikovaný URL a ověřeným SHA-256.
- Každá operace je spustitelná samostatně.
- Výstupy lze přegenerovat z PDF a modelového balíčku.

== Poznámky

Pipeline je navržena pro dlouhodobou udržitelnost a auditovatelnost.
Nevykonává právní interpretaci ani hodnotící analýzu obsahu.
